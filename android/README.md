# CamCoreEQ for Android

A thin shell around the same web app that runs on the player, with over-the-air updates.

## Install

Download `CamCoreEQ.apk` from [Releases](https://github.com/nzilberberg/CamCoreEQ/releases/latest)
and open it. Android will ask you to allow installing from your browser or file manager.

On first launch the app asks for your player's address (for example `192.168.x.x` or
`player.local`). Change it later in Settings → Player. It needs nothing else: the app talks
directly to CamillaDSP and to the player's CGI endpoints, and all your presets and settings
live on the player, so the app and a browser show the same state.

## Why an app rather than a hosted web page

A browser page served over HTTPS **cannot** talk to CamillaDSP at all. An insecure WebSocket
(`ws://`) from a secure page is active mixed content: browsers block it outright and never
upgrade it, and CamillaDSP has no TLS listener to upgrade to. That is a browser security rule,
not a limitation of this project.

The app sidesteps it by serving its own copy of the page from a loopback HTTP origin
(`http://127.0.0.1:8731`), which is insecure and therefore allowed to open `ws://`. That is why
`LoopbackServer` exists, and why moving to `WebViewAssetLoader` — which would give an `https://`
origin — would break every connection to the player. Please read `LoopbackServer.java`'s header
before changing how the document is loaded.

The port is fixed on purpose: the document origin includes it, `localStorage` is per-origin, and a
varying port would silently discard your settings on every launch.

## Updates

Two independent tracks.

**Web updates are automatic.** On launch the app fetches `build.json` from GitHub Pages, compares
its `build` to the copy it is serving, and if it differs downloads the new `index.html`. The swap
takes effect on the **next** launch, never mid-session — an EQ editor reloading itself while you
are dragging a band would lose the edit. The download is verified to actually be CamCoreEQ before
it is stored, and both files are committed atomically, so an interrupted download can never leave a
truncated app.

The fetch is done **natively**, not with `fetch()` inside the page: GitHub Pages sends no CORS
headers, so an in-page request would be refused. Native HTTP is not subject to CORS.

If the check fails — no internet, which is the normal case on an isolated LAN — the app keeps
running from its stored copy. The update is never a runtime dependency.

**Native updates are manual.** When this shell itself changes you must install a new APK. Bump
`versionCode` and `versionName` in `AndroidManifest.xml`, `NATIVE_VERSION` in `WebUpdater.java`,
and `nativeVersion` in `build.json`, all in the same commit. Raise `minNativeVersion` only when a
web build genuinely cannot run on an older shell; the app then refuses to swap to it and says so
rather than breaking quietly.

## Building

Needs an Android SDK (build-tools 35.0.0, platforms/android-35) and any JDK on PATH. No Gradle and
no AndroidX — the whole build is aapt2, javac, d8, jar, zipalign and apksigner:

```
node android/make-icon.mjs android/res/mipmap-xxxhdpi/ic_launcher.png 192
powershell -ExecutionPolicy Bypass -File android\build.ps1
```

Output: `android/build/CamCoreEQ.apk`.

The signing keystore is created on first build **outside** the repository and is not committed.
**Keep it.** Android refuses to update an app signed with a different key, so losing it means
every user has to uninstall and reinstall.

The icon is generated by script rather than committed as a binary, because a PNG in this project
was once corrupted by moving its bytes through a text channel.

## Files

| File | Role |
|---|---|
| `MainActivity.java` | WebView setup, system-bar insets, launches the OTA check |
| `LoopbackServer.java` | serves the document over an insecure loopback origin — read its header |
| `WebStore.java` | bundled vs downloaded copy, atomic commit, build comparison |
| `WebUpdater.java` | native OTA fetch, version floor, self-identification check |
| `res/xml/network_security_config.xml` | permits cleartext, with the reason it must be unscoped |
| `make-icon.mjs` | generates the launcher icon |
| `build.ps1` | the whole build |

## Known limits

- Not verified on a device yet. It compiles, signs and bundles the correct build, but no
  on-device run has been done.
- Assumes the player serves the EQ on port 8080 and CamillaDSP on 1234, the defaults.
- The app does not detect the player automatically; you enter its address once.
